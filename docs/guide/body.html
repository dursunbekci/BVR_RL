1 · What this project is

BVR RL trains an artificial pilot for beyond-visual-range (BVR) air combat: engagements where the two aircraft are tens of kilometres apart, see each other only on radar, and fight with radar-guided missiles of the AIM-120 class.

The pilot is a neural network. It is not programmed with tactics. It learns them by flying hundreds of thousands of simulated engagements and being rewarded for good outcomes. This is called reinforcement learning.

What the agent learns

  • Find and hold the enemy on radar. Its radar sees only ±60° off the nose, out to a range that depends on the enemy's size.
  • Shoot at the right moment. Too far and the missile runs out of energy; too close and the enemy shoots first.
  • Support its missile. Its missile needs radar updates until its own seeker locks on.
  • Defend. Turn away or across an incoming missile to make it miss.
  • Manage energy and altitude. Speed and height extend a missile's reach.

Formats

  • 1 v 1: one agent aircraft against one enemy. This is the main format.
  • 2 v 1: two agent aircraft, flown by the same network, against one enemy. They share radar tracks over a datalink (chapter 14).

2 · Installing and starting

What you need

  • A computer with Python 3.10 or newer. The project is used on Windows; it also runs on Linux.
  • About 2 GB of disk space for Python packages, plus room for models (each about 5 MB).
  • More CPU cores make training faster: each parallel environment uses one core.
  • A modern web browser for the GUI.

Install, step by step

  1. Get the code. Clone the repository and switch to the working branch: 
    git clone https://github.com/dursunbekci/BVR_RL.git
cd BVR_RL
git checkout feature/platforms-2v1
  2. Install the Python packages. 
    pip install numpy torch gymnasium stable-baselines3 sb3-contrib tensorboard websockets matplotlib
    The project was last tested with numpy 2.4, torch 2.14, gymnasium 1.3, stable-baselines3 and sb3-contrib 2.9, websockets 17.1, tensorboard 2.21.
  3. Check everything works. Run the test suite. It takes a few minutes and should end with 36/36 passed. 
    python test_sim.py
  4. Start the GUI. 
    python bvr_gui.py
    Then open http://localhost:5006 in your browser. The GUI uses two ports: 5006 for the page and 5010 for live updates.

Getting updates

When new code is pushed, stop the GUI (Ctrl+C), run git pull, and start it again. A training run that is already going keeps the code it started with; the changes apply to the next run.

3 · Your first training run

This run trains an F-16 against an F-16, starting with the easiest opponent. Everything happens on the TRAINING tab.

  1. Engagement. Set the format to 1 v 1, AGENT FLIES to F-16C, OPPONENT FLIES to F-16C.
  2. Opponent stage. Choose STRAIGHT. This is the first stage of the curriculum: an enemy that flies straight and never shoots.
  3. Missile doctrine. Leave it at MIXED. Each episode then uses one of three costs per missile fired, and the agent learns all three (chapter 10).
  4. Training steps. Start with 2,000,000. One step is one decision, which is one simulated second. The estimate under the field shows how long that takes on your machine.
  5. Parallel envs. Choose as many as you have spare CPU cores (4 or 8 on most desktops). Each runs its own simulation in a separate process.
  6. Gamma, learn rate, batch. Leave the defaults: 0.997, 0.00025, 256 (chapter 11 explains them).
  7. Auto-curriculum. Leave it ON. The opponent then gets harder by itself as the agent improves (chapter 12).
  8. Model name. Give the run its own name, e.g. f16_first. The final model is saved as models_bvr/f16_first.zip.
  9. Resume from. Leave it at fresh start.
  10. Start. Click ▶ START TRAINING. The first episode may take 30–60 seconds while the network is built.

What you'll see

  • The log prints a line every 10 episodes: win, loss, mutual and timeout shares, hit rate (Pk), shots per episode and more.
  • The dashboard fills in after the first 10 episodes: key numbers along the top and charts below. Chapter 16 explains each one.
  • The curriculum bar at the top shows the current stage and how close the agent is to advancing.

Stopping and saving

  1. Click ■ STOP at any time. The trainer saves the model before it exits; wait for "saved final model" in the log.
  2. The model appears as models_bvr/<model name>.zip. Along the way, the trainer also saves backups in models_bvr/archive/: the best model at each stage, and the model just before each stage change (chapter 22).
  3. To continue later, start a new run with RESUME FROM set to that file, and give the new run a new model name.

What a good first run looks like

Against STRAIGHT, the win rate should climb from near 0 to over 65% within a few hundred thousand steps, and the curriculum then moves on to EVASIVE. The track fraction should rise and timeouts should fall. If the win rate stays flat for a million steps, see chapter 21.

Long runs

For an overnight run, work out the steps from your machine's rate. Example from this project: 92 episodes a minute at about 210 steps each is about 1.16 million steps an hour, so 12 hours is about 14 million steps. Resume from your last model, keep the same number of parallel envs, and give the run a new name so it doesn't overwrite the previous model.

4 · Watching a trained model

The WATCH tab flies a saved model live, in a 3-D view, and sums up the episodes it plays.

  1. Checkpoint to load. Pick the model, e.g. f16_first.zip or an archive file. The list is read live from models_bvr/.
  2. Opponent. Pick who it fights. It doesn't have to be the opponent it trained against: e.g. train against STRAIGHT, then watch against SHOOTER to see what transfers.
  3. Playback speed. 3× is good for following tactics, 10× or 50× for scanning many episodes.
  4. Episodes. How many to play before stopping by itself: 10, 25 (default), 50, 100, 200, or until stopped.
  5. Missile doctrine. The missile cost the model is told about (BALANCED by default).
  6. Opponent flies and Format. By default, the platform and format the model was trained with.
  7. Click ▶ START EVAL.

What you'll see

  • The 3-D tactical view shows both aircraft, their trails and missiles. Blue is the agent, red the opponent.
  • Live engagement shows range, closure, track state, missile status and more for the current moment.
  • Watch statistics sums up the session: outcomes, win rate with its 95% range, exchange ratio, hit rate, shots, shot range, and win/loss by start geometry and start range (chapter 17).
  • Shot Trace (📋 in the log bar) lists every missile launch of the last episode: range, aspect, track quality, and where in the envelope it was fired.

WATCH is not the training dashboard

WATCH always takes the model's single most likely action. During training the model samples its actions, so it sometimes tries less likely ones. WATCH numbers can therefore differ from the training dashboard, usually upwards. For a proper comparison of models, use CROSS-PLAY.

5 · Comparing models with cross-play

CROSS-PLAY plays every chosen model against every other, in both seats, and optionally against scripted opponents. It runs without drawing, in parallel, so it's much faster than WATCH and gives fair, comparable numbers.

  1. Checkpoints. Tick the models to compare. Quick links select all, only the archive, or none.
  2. Scripted columns. Optionally add scripted opponents (e.g. SHOOTER, ADAPTIVE) as extra columns, to see how each model fares against them.
  3. Games per cell. 100 is a good default. More games give narrower uncertainty ranges.
  4. Workers. Parallel processes; use your spare CPU cores.
  5. Doctrine. Both sides fly the same missile doctrine.
  6. Click ▶ RUN CROSS-PLAY. The estimate under the fields shows the number of games and the expected time.

Reading the results

  • The matrix: each cell is the row model's score against the column model, with the row model in seat AC1. A win scores 1, a draw (mutual kill, timeout, escape) 0.5, a loss 0. Green is above 0.5, red below. The ± value is the 95% uncertainty range.
  • Head-to-head between two models: average both cells. For example, if v5 scores 0.67 against v4 and v4 scores 0.56 against v5, v5's score is (0.67 + (1 − 0.56)) / 2 ≈ 0.56.
  • Elo ratings rank all models on one scale with a mean of 1000. A 100-point gap means the higher model scores about 0.64 against the lower one.
  • Seat bias is how far the AC1 seat scores above 0.5 when the same starts are played both ways. It cancels in head-to-head scores and Elo, since every pairing is played from both seats (chapter 18).

Every pairing starts from the same geometries

Game i of every pairing starts from the same geometry, so differences between cells come from the models, not from the luck of the draw.

6 · The simulated world

Everything runs in Python, 50 times per simulated second. The agent decides once per second; between decisions, the simulator flies its last command.

6.1 Aircraft

Each aircraft is a point-mass flight model with an autopilot. The agent does not move the stick: it chooses a heading, a target altitude and a speed, and the autopilot flies there within the aircraft's limits (turn rate, climb angle, thrust, drag, fuel). Two platforms ship with the project:

PlatformSpeed choices (m/s)MissilesRadar size (RCS)Operating altitude
F-16C220 · 280 · 340 · 40041.2 m²1,000–14,000 m
GENERIC-UCAV170 · 200 · 225 · 25020.1 m²1,000–12,500 m

The generic UCAV is illustrative, not data for a real aircraft. Both are defined in the parameter library (chapter 15).

6.2 Missiles

The missile model is of the AIM-120 class. A missile's life:

  1. Boost (6 s): the motor burns and the missile accelerates.
  2. Midcourse: it flies towards where the shooter's radar says the target is, updated over a datalink. If the shooter stops sending updates for 3 seconds, the missile is lost (the "3-second support rule").
  3. Hand-off: within 8–16 km of the target (less against a small target), its own seeker locks on. From then on it no longer needs the shooter.
  4. Terminal: it steers itself to the target, pulling up to 30 g. It kills inside a 10 m radius, misses if it runs out of energy, and is gone after 120 s at most.

Launch envelope. How far a missile can reach depends on the shooter's speed and altitude and on the target's direction of flight and altitude. Head-on, the target flies into the missile, so the reach is longest; tail-on it is several times shorter. A target far below makes the missile end its flight in thick air: from 9 km, the AIM-120C-DCS reaches 84 km head-on against a level target, 58 km against one at 1 km (target altitude is measured since SIM_REV 11). The project measures this once per missile type with sweep_envelope.py and stores it as a table. Two numbers come out of it:

  • Rmax: the farthest range at which a shot can hit a target that keeps flying as it is.
  • RNEZ (no-escape zone): the range inside which a shot hits even if the target turns and runs at once.

6.3 Radar

Each aircraft has a radar model that behaves like a radar that has already locked onto the target. It does not search or scan.

  • Coverage: ±60° off the nose, left/right and up/down.
  • Range: the platform's maximum range (90 km for the F-16C's radar, 70 km for the UCAV's) scaled by the target's size: range × (target RCS / 1.2 m²)¼. A small UCAV (0.1 m²) is seen at only about 54% of the range of an F-16.
  • Errors grow with the square of range, are about 4 times larger when the target flies across the line of sight (low closure, the "Doppler notch"), and drift smoothly rather than jumping (about 2 s correlation).
  • Rate: 10 reports per second.

6.4 Track

The radar reports are turned into a track: an estimate of the target's position and velocity, with an uncertainty. The track has four states:

NONEno target known
→
ACQUIRINGreports coming in; not yet firm
→
TRACKfirm: 5 reports in a row. Missiles can be fired.
→
COASTno report for 0.5 s; position estimated forward, uncertainty grows
  • A new report brings a COAST track back to TRACK.
  • After 15 s without reports, the track is dropped (NONE).
  • If the position uncertainty grows beyond 2 km, the track falls back to ACQUIRING.

6.5 What the opponent knows

Scripted opponents see the true positions: they never lose track. That is deliberately in the agent's disfavour, so that beating them is a real result. In self-play, the opponent copy has its own radar and track, exactly like the agent.

7 · One episode, step by step

7.1 The start

Each episode starts with the two aircraft 70–110 km apart, the first at 6–11 km altitude and the second within 2.5 km of it or, in half the starts (since SIM_REV 13), anywhere from 2 to 12.5 km, at 250–320 m/s (scaled to slower platforms). One of five start geometries is drawn:

Mirrored starts. In four of the five geometries, AC1 has the better start. So in half the episodes the two aircraft swap starts: the opponent gets the better one. The agent learns to fight from both sides. WATCH statistics mark mirrored starts with ⇄.

7.2 Each second

  1. The agent receives its 68 inputs (chapter 8), together with the previous 7 seconds' inputs.
  2. It chooses a heading, an altitude change, a speed and whether to fire (chapter 9).
  3. The simulator flies 50 small steps (1 s) with that command. The radar reports 10 times, the opponent acts, missiles fly.
  4. The agent receives the reward for that second (chapter 10).

7.3 The end

OutcomeWhen
KILLThe opponent is destroyed by the agent's missile.
SHOT_DOWNThe agent is destroyed by the opponent's missile.
MUTUAL_KILLBoth are destroyed. A kill ends the fight only once no missile is still in flight at a live aircraft, so a shooter that is hit can still take its killer with it.
TIMEOUT300 decisions (300 s) pass with no result. The limit is MAX_STEPS in bvr_env.py; slow platforms may need more (chapter 21).
ESCAPEThe range grows beyond 150 km.
CRASHThe agent flies below 300 m.
BANDIT_CRASHThe opponent flies below 300 m.

8 · What the agent sees

Every second the agent receives 68 numbers. Each is scaled to the range −1 to +1. The agent also gets the previous 7 seconds' numbers (8 frames in all), so it can see how things are changing.

Important: everything about the enemy comes from its own radar track, never from the true position. If the track is poor, the agent's picture is poor.

GroupInputsWhat they are
Own aircraft10Mach, altitude, climb angle, bank angle, load factor, energy, angle of attack, missiles left, fuel.
Track14Track state (NONE / ACQUIRING / TRACK / COAST), range, closing speed, angle off the nose (left/right and up/down), the enemy's aspect (which way it points relative to us), track age, position and velocity uncertainty.
Enemy estimate4Enemy speed, altitude difference, energy difference, line-of-sight rate.
Envelopes4Range ÷ own Rmax, range ÷ own RNEZ, and the same for the enemy's missile against us. Below 1 means "inside".
Own missiles6Missiles in flight, nearest one's time-to-go, time in flight, whether it still needs support, whether its seeker is active, time since its last update.
Threat warning6Missile launch warning, how long ago, its bearing, whether its seeker is active, time-to-go of the nearest inbound missile.
Time and doctrine3Fraction of the episode elapsed, time since the last shot, the doctrine's cost per missile.
Wingman (2v1)17The wingman's position, heading, speed, track, missiles and threats. All zero in 1v1.
Heading4The previous heading choice and the turn still to fly.
68

The critic sees more

The network has two halves (chapter 11). The actor chooses actions and sees only the 68 inputs above. The critic judges how good a situation is, and during training also gets 24 true values: true range, closure, aspects, energy, the enemy's missiles and so on. This helps it learn faster. The critic is not used when the model flies, so the agent never relies on information it couldn't have.

9 · What the agent can do

Once per second the agent makes four choices at once:

ChoiceOptionsMeaning
Heading0, ±15, ±30, ±40, ±50, ±90, ±135, 180°An offset from the bearing to the enemy. 0 = straight at it, ±40–50 = crank, ±90 = beam, 180 = straight away. Positive = to the right. With no track, the offset is from the last known bearing. ±15 and ±40 since SIM_REV 14: the policy kept alternating 0 ↔ 30 and 30 ↔ 50 (its two most frequent heading changes) to fly something in between.
Altitude−3000, −1200, 0, +1200, +3000 mChange of target altitude from the current one, kept inside the platform's operating band.
Speedthe platform's 5 speedsF-16C: 220, 280, 340, 400, 460 m/s; at 9 km Mach 0.73, 0.92, 1.12, 1.32 and 1.52 (the fifth, since SIM_REV 14, is the DCS AI's Mach 1.5 dash in combat).
Fireno / yesLaunch a missile this second.

An older checkpoint (10 headings, 4 speeds) is converted when it is loaded: each old choice keeps its own output, and each new one starts from the average of its neighbours' (±15 between 0 and ±30, ±40 between ±30 and ±50, 460 from 400), a quarter as likely as they are. It flies as before until training finds a use for the new choices, so a resume is a warm start.

The fire rule

"Fire" can only be chosen when all of these hold. Otherwise it is masked, meaning the network cannot pick it:

  1. Missiles are left.
  2. The track is firm (TRACK state).
  3. At least 3 s have passed since the last launch.
  4. The target is within 60° of the nose. The missile leaves along the aircraft's axis and must turn; beyond 60° it loses most of its reach.
  5. The range is between 1.5 km and Rmax.

Inside that window, choosing when to fire is up to the agent. The reward encourages shots at 0.6–0.85 of Rmax, where hits are likely.

Changing heading costs a little

Each change of the heading choice costs 0.02 per 180° of change (chapter 10; 0.04 until SIM_REV 15). Without it, policies flipped between two similar choices every few seconds, rocking their wings. A deliberate defensive turn still costs very little.

10 · How the agent is rewarded

The reward is what the agent tries to maximise. It has three parts.

10.1 Outcome (last second only)

OutcomeRewardWhy
KILL+1.0The goal.
SHOT_DOWN−1.0The worst result.
MUTUAL_KILL−0.4Trading aircraft is bad, but better than only losing.
TIMEOUT−0.8Avoiding the fight is not a solution. (−0.5 until SIM_REV 15: a reward at the end of a 400-step episode is worth only 0.30 of its face value at γ = 0.997, and the heading cost, paid as it goes, made a timeout worse than being shot down.)
ESCAPE−0.6Running away is worse than a timeout.
CRASH−1.0Flying into the ground is as bad as being shot down.
BANDIT_CRASH+0.4The opponent crashed, often while defending.
Each wasted missile−0.03Every missile that did not make the kill.

10.2 Shaping (every second)

An episode can last 300 seconds, and the outcome comes only at the end. To help the agent learn which seconds mattered, every second also gets a small shaping reward: the change in a score Φ ("potential") of how good the situation is. Because it is only the change, it speeds up learning without changing what the best tactics are.

reward each second = γ·Φ(after) − Φ(before) − heading cost − shot cost

10.4 2v1 team rewards

In 2v1 both aircraft share a team reward: +1.0 when the enemy is destroyed, −1.0 for each blue aircraft shot down, −1.0 for a crash, −0.8 for a timeout, −0.6 for an escape, +0.4 if the enemy crashes. Each aircraft also gets its own shaping and costs.

Where to see it

On the TRAINING page, REWARD DRIVERS shows how much each shaping term and cost has moved the reward recently. A term near zero isn't influencing learning; a dominant one may be steering it too much.

11 · How the agent learns

11.1 The method: PPO, in plain words

  1. Fly. Each parallel environment flies 1,024 decisions with the current network, recording inputs, choices and rewards.
  2. Judge. The critic estimates how good each situation was. Comparing that with what actually followed shows which choices turned out better or worse than expected.
  3. Improve. The actor is nudged to make the better choices more likely, in 6 passes over the data in batches of 256. PPO limits each nudge (the "clip") so that one batch can't change the network too much.
  4. Repeat until the training steps are used up.

11.2 Settings

SettingValueMeaning
Gamma (γ)0.997How much future rewards count. A missile flies about 40 s, so a launch decision is 40 steps from its result. At 0.997, 89% of the result reaches the launch; at 0.99 only 67%; at 0.95 13%.
Learning rate0.00025Step size of each update. Lower if updates are unstable.
Steps per update1,024Per environment. Long enough to cover a whole engagement.
Batch size256Decisions per gradient step.
Passes6Passes over each batch of data.
Clip0.2Limit on how far one update may change the choice probabilities.
Target KL0.02Stops an update early if it changes the network too much.
Entropy0.01Keeps the agent exploring.

11.3 Masks

Impossible choices are removed before the network chooses (for example, firing without a firm track). This is "MaskablePPO". The agent never wastes time learning that impossible choices don't work.

12 · The curriculum and the opponents

SELF-PLAYyesFrozen copies of the agent itself (chapter 13).Beat an opponent as good as itself.

In 1v1, SHOOTER and ADAPTIVE fly under the agent's rules (since SIM_REV 9): each runs its own copy of the radar model, aims its missiles at its own track and fires only when the agent would be allowed to. A red that turns too far off loses its track, and its missile misses after 3 s without support, as the agent's would. Before, red's missiles were guided by the true position, so red could crank wider and still hit. The 2v1 opponents are unchanged.

Red's bearing to the agent (fixed in SIM_REV 13). Every scripted manoeuvre steers relative to the bearing from red to the agent. It used to be rebuilt from red's heading and an angle that has no sign, so with the agent on red's left it came out mirrored: 30–177° wrong in 15 of 40 fights. A red told to go hot first turned away and looped round; its cranks, drags and beams went the wrong way. It now comes from the two positions. ADAPTIVE is much stronger for it: dcs_v8 won 68% of 120 fights against it before the fix, 50% after, and was shot down three times as often.

The deep dives (SIM_REV 10) matter because of the missile's energy: after its motor burns out it coasts, and the thick low air drains it. Against a level AIM-120C-DCS shot from 9 km, a red that turns away and dives escaped shots from 29 km that hit every beaming target. No ground clutter is modelled, so diving doesn't hide a target from the radar.

When does it advance?

The curriculum moves on when all three hold:

  1. At least 60 episodes have been played at the current stage (MIN EPISODES / STAGE). This makes sure the 50 episodes it judges are all against the current opponent.
  2. The win rate over the last 50 episodes is at least 65% (ADVANCE AT).
  3. It has stayed there for 5 checks in a row, one check every 10 episodes (HOLD FOR). A single lucky streak isn't enough: with 1 check, an agent that really wins 55% passed a 65% mark within 1,000 episodes 97% of the time; with 5 checks, 29%.

All three are set per run on the TRAINING page. For a mismatched matchup (e.g. two UCAVs against an F-16), 65% may be out of reach: lower ADVANCE AT.

At each advance, the model just before the change is saved as archive/pre_<STAGE>.zip. The best model at each stage is saved as archive/best_<STAGE>_<win rate>.zip.

13 · Self-play

In self-play the opponent is a frozen copy ("snapshot") of the agent itself. It only exists in 1v1 with both sides on the same platform, since a copy of the agent can only fly the aircraft it was trained on. The exception is two platforms that differ only in how they are flown and in what their five speed choices are, such as F-16C-DCSAI (the agent, flown like the DCS AI on a route: climbs at Mach 0.85, turns at no more than 45° of bank) or F-16C-DCSAI-AD (the same, defended automatically while a missile is inbound) and F-16C-DCS (red): the same aircraft, inputs and choices.

Step by step

  1. The pool starts empty. At the start of every training run, the snapshot pool (models_bvr/selfplay_pool/) is emptied, so a run only ever meets copies of its own policy.
  2. First snapshot. When the SELF-PLAY stage begins, the current policy is saved into the pool.
  3. More snapshots. Every 250,000 steps another is added. The pool keeps the newest 12, about the last 3 million steps of the policy.
  4. Each episode, an opponent is drawn:
    • 1 in 3 episodes: the scripted ADAPTIVE shooter, so a committed attacker stays in the mix. Without it, self-play tends to settle into both sides turning away at long range.
    • Otherwise, half the time the newest snapshot, and otherwise a random snapshot from the pool. Facing older versions stops the agent forgetting how to beat them.
  5. The snapshot flies fairly. It has its own radar and track, the same inputs, the same firing rule, its own missile guidance, and its own doctrine.
  6. Only the agent learns. Snapshots are frozen.

Watching it

  • The log and TensorBoard split the win rate into against snapshots and against scripted. Around 50% against snapshots means parity with its recent selves.
  • If the win rate against scripted falls while the rate against snapshots rises, the agent is overfitting to its own style: raise the scripted share.
  • SELF-PLAY is the last stage; the curriculum doesn't advance beyond it.

Settings (SELF-PLAY section of the TRAINING page)

SettingDefaultChange it when
Scripted share33%Raise if the agent overfits to its own style; lower if the scripted shooter is already beaten easily.
Newest share50%Lower if it forgets how to beat older versions; raise for harder, more current opposition.

14 · Two against one (2v1)

In 2v1 two blue aircraft fight one red. Both blue aircraft are flown by the same network; each gets its own inputs and makes its own choices.

  • Datalink. If an aircraft has no firm track of its own, it uses its wingman's, with 150 m extra uncertainty and 0.2 s delay. It can even fire on it.
  • Wingman inputs. 17 of the 68 inputs describe the wingman: position, heading, speed, track, missiles, threats.
  • Formation. The wingman starts beside the lead (abreast), behind it (trail) or behind and to the side (echelon).
  • Red's targeting. Red opens on the nearer blue aircraft and switches only if the other gets much closer. While cranking, SHOOTER and ADAPTIVE also fire at the other blue aircraft if it is in range and within 60° of red's nose.
  • Rewards. Team rewards (chapter 10.4). A mutual kill (red destroyed, one blue lost) is worth 0, between a clean kill (+1) and a timeout (−0.8).
  • No self-play yet. Red is always scripted, so the 2v1 curriculum ends at ADAPTIVE.

Lessons from 2v1 training

  • With a lost aircraft costing only −0.7, the team learned to sacrifice the lead as bait and kill with the wingman: 90% mutual kills. The cost is now −1.0, and red also shoots the second aircraft.
  • UCAVs are slower than F-16s. With a 300 s limit, even ideal play timed out on most starts beyond 85 km. Raise MAX_STEPS (400–480) for slow platforms.

Making your own aircraft, step by step

  1. On the LIBRARY tab, open a built-in item and click ⧉ Copy…. Built-ins are never changed.
  2. Edit the copy's values and click ✔ Save. Each value has a unit, a valid range and a source note.
  3. For an airframe or platform, click ▶ Performance card: it flies the flight model and reports top speed, turn, climb, ceiling and autopilot behaviour, with warnings.
  4. For a missile, click ⟳ Calibrate envelope (or python sweep_envelope.py --missile <id>). Training refuses to start until a missile has an envelope for its exact values. The file name carries a fingerprint, so editing the missile invalidates the old table. A table calibrated before SIM_REV 11 has no target altitude and assumes a level target; training says so at the start. Recalibrate it.
  5. Select your platform under ENGAGEMENT on the TRAINING page.

Old models keep their meaning

Every checkpoint stores the platforms and the full items it was trained with. Later edits in the library never change what an old checkpoint means.

18.2 How games are scored

  • Win = KILL or BANDIT_CRASH (1). Loss = SHOT_DOWN or CRASH (0). Draw = MUTUAL_KILL, TIMEOUT or ESCAPE (0.5).
  • The row model flies AC1; the column model AC2, with its own radar and track.
  • Game i of every pairing starts from the same geometry. Both orders (A v B and B v A) are played on the same starts.
  • Models take their most likely action (sampling can be switched on from the command line).

18.3 Seat bias

A model against itself should score 0.5. The difference is the AC1 seat's advantage. Starts used to be drawn from AC1's side, which gave AC1 a real head start (a bias of about +0.13). Since half the starts are now mirrored, the bias should sit near 0. Either way it cancels in head-to-head scores and Elo, because every pairing is played from both seats. A large bias usually means few games per cell.

18.4 Elo

A rating for each model and scripted opponent, fitted over all games, mean 1000. 100 points ≈ a 0.64 expected score for the higher-rated side.

20 · Reading a training run

A healthy run

  • Track fraction rises first. The agent learns to point its radar at the enemy before it learns to shoot well.
  • Win rate rises and timeouts fall at each stage, then dip after each advance and recover. A dip is normal: the new opponent is harder.
  • r/Rmax at shot settles in 0.6–0.85, and Pk rises.
  • Bank reversals stay at a few a minute.

Judging progress fairly

  • Training numbers move with the opponent. A lower win rate after an advance, or after a change such as mirrored starts, doesn't mean a worse model.
  • Compare models in CROSS-PLAY, on the same starts, from both seats, many games.
  • Use WATCH statistics to see where a model wins and loses: by start geometry and range.
  • Watch some episodes. Several problems in this project were found by watching: the dive in 2v1, wing-rocking, hesitation at the start.

TensorBoard

Training also writes to tb_logs_bvr/. Start TensorBoard with tensorboard --logdir tb_logs_bvr for more detail: PPO internals (clip fraction, KL), every reward term, the win rate split by opponent kind in self-play, and heading switches per minute.

PPO health check

If the clip fraction stays around 0.25 or higher, and the KL around 0.02 (the stop threshold), updates are large. Lowering the learning rate (e.g. to 0.0001) often makes training steadier.

24 · DCS World: first step

The long-term aim is to fly a trained model in DCS World. Training stays in this simulator, since DCS runs in real time and has no quick reset. The first step, already built, checks whether a policy's inputs would look the same in DCS as in training.

  1. Allow file access for mission scripts: in <DCS>\Scripts\MissionScripting.lua, comment out sanitizeModule('io') and sanitizeModule('lfs'). While they are off, any mission can read and write files on your computer; restore them afterwards.
  2. Build a mission with one blue and one red jet, 60–110 km apart, and a MISSION START trigger running dcs/bvr_logger.lua (DO SCRIPT FILE).
  3. Fly it. The logger writes Saved Games\DCS\Logs\bvr_rl_*.jsonl, 10 times a second.
  4. Check it: python dcs_obs_check.py <file> --platform F-16C --opp-platform F-16C --max-steps 400. Inputs flagged OUTSIDE or CLIP are ones the policy has rarely or never seen.

Details in dcs/README.md. Only 1v1 so far. The logger has been tested against a mock of the DCS scripting API, not yet inside DCS.
